Deployment of payment-service v3.8.0 enabled in-memory session caching with no eviction policy and no size limit. Each user session was cached in a HashMap that grew unbounded, reaching 104,800 sessions and consuming 3.4GB of heap. This caused increasingly long GC pauses (up to 8.5s), request timeouts, and eventually OOM kills. The service restarted but immediately began leaking again due to the same configuration.
