A rolling deployment of search-api v4.2.0 to prod-app-01 included database credentials from a new Vault path (vault/search-api/v4.2.0/db-creds) that contained an incorrect password. The old version on prod-app-02 continued using valid credentials from vault/search-api/v4.1.5/db-creds. The deployment health check only verified HTTP 200 status, not database connectivity, so the rollout proceeded despite the app running in degraded mode. With 50/50 load balancing, 45% of all search requests hit the broken instance and returned 500 errors.
